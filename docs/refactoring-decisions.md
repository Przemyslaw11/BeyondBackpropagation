# Refactoring decision register

This register separates confirmed source behavior from intentional corrections.
Corrections must have a regression test before they become part of the canonical
runtime.

| ID | Decision | Scientific impact | Status |
| --- | --- | --- | --- |
| SCI-001 | Preserve repository paper metadata `arXiv:2511.01061v1`; record the conflicting `2509.19063v1` brief identifier without rewriting citations. | Citation provenance remains auditable. | recorded |
| CFG-001 | Use deterministic base-plus-experiment deep merge with list replacement and explicit CLI overrides. | Resolved configurations become reproducible. | implemented in canonical loader |
| CFG-002 | Repair the malformed CaFo CIFAR100 tuning YAML and normalize `input_channels'`, misplaced CaFo early-stopping keys, and `epochs_per_block` aliases. | No intended algorithmic change; invalid input becomes actionable. | implemented with regression test |
| CFG-003 | Apply repeated CLI `--set section.key=value` overrides after base and experiment YAML merging and before strict validation. | Command-line reproducibility is explicit and precedence is testable without changing the source YAML. | implemented with regression tests |
| DATA-001 | Forward `data.download` through the canonical data policy. | Dataset acquisition behavior becomes explicit. | implemented with regression test |
| DATA-002 | Register MNIST, Fashion-MNIST, CIFAR-10, and CIFAR-100 with explicit channel, image-size, class-count, and split metadata; move preprocessing behind the canonical namespace while retaining a legacy shim. | Dataset identity and transform semantics become inspectable without changing the published protocol. | implemented with regression test |
| DATA-003 | Move the complete loader implementation behind `beyond_backprop.data.loaders`; retain module aliases for legacy imports and preserve explicit download forwarding, fixed/random split rules, transform isolation, and backend loader precedence. | The data boundary is testable without downloading data; no dataset protocol or published value changes. | implemented with regression tests |
| ARCH-001 | BP baselines use standard classifier modules; MF BP baselines contain no projection matrices. | Removes algorithm-specific trainable state from BP comparison. | implemented with regression test |
| ARCH-002 | CaFo dummy shape inference runs in evaluation mode and restores module state. | Prevents BatchNorm running-stat mutation during construction. | implemented in fair baseline builder |
| ARCH-003 | Native and fair-baseline architecture construction is selected through explicit registry entries rather than central conditional dispatch. | Architecture parity becomes testable and extensible without changing model mathematics. | implemented with regression test |
| MET-001 | Canonical accuracy fields use percentage points (`0–100`); persisted metrics include units and provenance. | Prevents factor-of-100 interpretation errors. | implemented in contracts |
| MET-002 | Training is the default canonical measurement region; setup and evaluation are excluded. | Efficiency comparisons remain definitionally clear. | recorded |
| BUG-001 | Legacy `run_experiment.py` removes the obsolete CodeCarbon result key. | No scientific effect; avoids misleading cleanup. | implemented with regression test |
| BUG-002 | Initialize cleanup state before `run_training()` enters its `try` block. | Failed setup paths finalize safely. | implemented with regression test |
| RUN-001 | Register BP, FF, CaFo, and MF as canonical adapters that delegate to the established mathematical routines while exposing typed fit/evaluate results and algorithm-specific lifecycle markers. | Training mathematics, optimizer semantics, local stages, aggregation, projection behavior, and inference remain unchanged while shared orchestration becomes replaceable. | implemented with synthetic regression tests |
| RUN-002 | Keep tracking/resource services injectable and default to no-op implementations in the canonical runner; cleanup finalizes monitors and trackers on success and failure. | CPU experiments do not require W&B, NVML, CodeCarbon, CUDA, or GPU state; disabled instrumentation does not alter algorithm results. | implemented with synthetic regression tests |
| RUN-003 | Restore best state through adapter lifecycle hooks and canonical checkpoint payloads when available; legacy checkpoint names remain owned by the existing routines. | Restart and best-state behavior stays compatible without forcing BP, FF, CaFo, and MF into one loop. | implemented with synthetic regression test |
| ALG-001 | Extract FF label embedding/schedule/goodness, CaFo predictor aggregation/loss, and MF projection/local-loss formulas into dependency-light canonical math modules; legacy entry points delegate to them. | Numerical behavior remains covered by deterministic tensor tests while the next migration can remove infrastructure from training code. | implemented with numerical regression tests |
| MET-003 | Persist canonical `config.resolved.yaml`, `metadata.json`, `metrics.json`, `history.csv`, and `summary.json` artifacts while retaining the historical config and summary filenames as aliases. | Run provenance and metric units become machine-readable without invalidating existing restart and analysis paths. | implemented with runner and tracker tests |
| OBS-001 | Keep W&B, NVML, and CodeCarbon imports lazy and report unavailable optional services through explicit no-measurement snapshots. | CPU smoke tests remain offline and scientific measurements are never presented as available when the required service is absent. | implemented with adapter tests |
| OPS-001 | SLURM manifests and config paths are validated before submission. | Prevents silent omissions in batch experiments. | implemented with shell regression tests |
| OPS-002 | Add canonical `experiment run`, `tune`, `batch`, and `--dry-run` commands while retaining the original validation and inspection commands. | Local and batch entry points share typed config resolution; dry-run validation avoids dataset access and training side effects. | implemented with CLI regression tests |
| SCI-002 | Treat `arXiv:2509.19063v1` as the authoritative paper identifier for this refactoring; existing repository citations to `arXiv:2511.01061v1` (README badge, BibTeX) remain in place as cross-references and are not rewritten. | Citation provenance stays auditable while a single authoritative ID governs external references to the migrated code. | recorded |
| MIG-001 | Canonicalize all architectures under `beyond_backprop.architectures.{ff_mlp,mf_mlp,cafo_cnn}` with an explicit factory; legacy `src/architectures/*` modules become reverse shims re-exporting canonical names. | Model construction has one implementation; legacy imports keep working without duplicating model mathematics. | implemented with characterization tests |
| MIG-002 | Merge FF, MF, and CaFo trainer bodies verbatim into `beyond_backprop.algorithms.{ff,mf,cafo}`; legacy `src/algorithms/*` modules are shims. Checkpoint naming and result-dict shapes are preserved. | Training mathematics and orchestration have a single home; numerical behavior is guarded by adapter and lifecycle tests. | implemented with synthetic regression tests |
| MIG-003 | Retire the dual legacy experiment path: delete `src/training/engine.py`, `src/baselines/`, `src/tuning/optuna_objective*.py`, and the legacy monitoring/profiling/config-parser utilities; convert remaining `src/utils/{helpers,logging_utils,metrics}.py` into canonical re-export shims. Wrapper scripts (`run_experiment.py`, `run_optuna_search.py`) always translate to canonical CLI commands. | One execution path exists end-to-end; BUG-001/BUG-002 semantics are covered by canonical runner tests rather than duplicated legacy engines. | implemented; legacy-defect tests superseded by canonical equivalents |
| TEST-001 | Organize the test suite into `tests/{unit,integration,regression,smoke,fixtures}`; pytest markers (`slow`, `gpu`, `smoke`) remain the selection authority for `make test-fast` and `make smoke`. | Test scope is discoverable by directory while CI selection semantics stay unchanged. | implemented; 84 CPU/non-slow/non-GPU tests green post-move |
| OPS-003 | Generate the SLURM array config manifest exactly once per array job (atomic `mkdir` lock, published via temp-file rename), scope the default manifest path to `SLURM_ARRAY_JOB_ID`, treat an explicit `CONFIG_MANIFEST` as trusted input, and read the manifest with a bash-3.2-compatible loop instead of `mapfile`. | Removes O(N·M) per-task YAML revalidation and concurrent write/truncation races that could mis-map array task IDs; readers only ever observe complete manifests. | implemented with shell integration tests |
| MIG-004 | Remove remaining src/* re-export shims and scripts/_migrate_b2.py; historical src.* import paths stop working (clean break). | No behavioral change; single canonical namespace. | implemented |
| EVAL-001 | Evaluation no longer substitutes predictions on internal failures: FF forward errors, CaFo predictor/aggregation failures, and MF index guards abort evaluation with an exception (zero tolerance - a single failed batch fails the run). The runner records `RunStatus.FAILED` and the CLI exits non-zero. | Prevents silent metric corruption that could invalidate published accuracy deltas; published values are unaffected because reference runs had no failed batches (assumption verified by unchanged healthy-path results). | implemented with eval failure semantics and runner propagation tests |
| BEST-001 | FF final evaluation uses best-validation weights regardless of checkpointing configuration: `train_ff_model` accepts an `on_best_epoch` callback that captures an in-memory snapshot at each best epoch, restored by `AlgorithmAdapter.restore_best_state`; the legacy `ff_<exp>_best.pth` disk round-trip before final evaluation was removed. Checkpoint files on disk (naming and payload) are unchanged. | Reported test accuracy no longer depends on an unrelated config flag; legacy null-checkpoint-dir runs evaluated last-epoch weights, so those historical numbers may differ from re-runs under the new contract (call out when reproducing pre-2026-08 results). | implemented with best-state selection tests pinning identical evaluated weights with and without checkpoint_dir |
| BEST-002 | MF/CaFo evaluate the final trained state; no best-selection is defined for these local-stage algorithms (their trainers have no validation-based selection point by construction). | Matches the paper protocol of reporting the final trained stage; behavior is unchanged, now documented as intentional rather than incidental. | recorded; covered by existing synthetic lifecycle tests |
| CFG-004 | Strict unknown-key rejection for `algorithm_params`, resolved per algorithm (`bp`/`cafo`/`ff`/`mf` allow-lists; base templates without `algorithm.name` fall back to the union). Legacy dead keys present in tracked configs (`threshold` for FF, `lr`/`weight_decay`/`optimizer_type` for CaFo) stay tolerated and are marked in source. `ExperimentRunner.run` logs the resolved `algorithm_params` at INFO so every run records what actually executed. | Typos such as `predictor_lerning_rate` now fail validation instead of silently training with defaults; existing YAMLs are unaffected (all 44 validated exhaustively by test). No effective values changed. | implemented with strict-validation unit tests and a parametrized all-YAML sweep |
