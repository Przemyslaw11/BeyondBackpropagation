## 3. W3 per-cut redo — confirmed

Source: `jpdc_data/g1/w3_cut/w3_cut_summary.md`,
`scripts/jpdc/w3_cut_communication.py`.

- Unit: one activation tensor crossing one cut = `45,000 × 2,000 × 4 B =
  0.360 GB` per epoch per direction per cut. The hook measurement and the
  closed form agree to <1e-9 GB.
- BP: `2.16 GB/pass` (three cuts, forward activation + backward gradient).
- MF-Simul: `1.08 GB/pass` (three forward activations, no backward across a cut).
- MF-Seq useful: `0.36 GB` per prefix cut per stage epoch; W2 = 0.36, W3 = 0.72.
- Bytes-to-stopping, C10: BP **114.4**, MF-Simul **62.9**, MF-Seq useful
  **30.0**, as-implemented **83.4 GB**.
- Bytes-to-stopping, C100: BP **94.8**, MF-Simul **38.6**, MF-Seq useful
  **26.5**, as-implemented **74.4 GB**.
- Dead M0 forward: **1.08 GB/pass**; **64.1%** (C10) / **64.4%** (C100) of
  as-implemented MF-Seq bytes.
- Cached-prefix counterfactual (augmentation disabled): **22.1%** (C10) /
  **25.3%** (C100) saving of useful bytes. CIFAR crop/flip makes the cached
  prefix invalid for canonical runs, so this is a bound, not a deployable result.
- The old **69.1 GB/pass** is **memory traffic**, not cut communication: 4.881
  forward-activation + 19.951 forward-parameter + 4.327 backward-activation +

## 6. W6 toy numerics — exploratory only

Source: `scripts/jpdc/w6_toy_sim.py`, output `jpdc_data/g1/w6_toy/`.

There is no W6 preregistration in the repository. This is a CPU-only sanity
check on a deep-linear synthetic regression task (d=8, hidden=4, rank-2 teacher,
10 seeds, 420 Adam steps). It is **not confirmatory**, not pooled with W1–W4,
and not a hypothesis test.

| method | mean held-out MSE | ratio to BP |
|---|---:|---:|
| BP (420 updates/layer) | 5.08e-06 | 1.00× |
| MF-Simul (420/layer) | 3.11e-06 | 0.61× |
| MF-Seq (420 total, 140/stage) | 1.05e-03 | 205.8× |
| Seq-Global (420 total, 140/stage) | 1.19e-05 | 2.35× |

**Budget confound.** BP updates every layer 420 times; MF-Seq and Seq-Global
split 420 total updates across three stages, so the headline 205.8× is not a
clean staging comparison. Controls (same 10 seeds): BP-140 = 5.24e-04
(103.2× BP-420); MF-Seq-1260 = 8.69e-06 (**1.71×** BP-420); Seq-Global-1260 =
1.15e-06 (**0.23×** BP-420). The MF-Seq gap shrinks by two orders of magnitude
when per-layer updates are matched, so the toy must not be used to argue that
staging itself helps. The Seq-Global-1260 figure is not a clean equal-update
control: its prefix receives 420–1260 cumulative updates, versus 420 for every
layer under BP-420. See the budget-audit table in `w6_toy_summary.md`.

Gradient diagnostic at initialisation: cosine(global BP, first local head) =
−0.13 mean (median −0.09, SD 0.27). The toy shows that a frozen greedy prefix
can be badly suboptimal on this linear task and that stagewise unfreezing does
not automatically recover BP; it does not establish a mechanism. A confirmatory
W6, if wanted, needs its own addendum with task family, seeds, metric, and
thresholds.
